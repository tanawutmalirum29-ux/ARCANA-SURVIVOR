# Year-One Event Catalog — 12 Campaigns + Recurring Modes

**นี่คือแผนคอนเทนต์ ไม่ใช่การประกาศว่า event เปิดจริงแล้ว**. ใช้ campaign slots 3 รอบต่อซีซัน (W02–03, W05–06, W08–09), เป็น blueprint สำหรับ config ของ event engine. Season finale W10–12 เป็นความคืบหน้า chapter/pass แยกจากสามอีเวนต์นี้.

## 1. Universal event contract
- ทุกอีเวนต์มี free main cosmetic เส้นทางรับอย่างน้อยหนึ่งเส้นทาง, starter reward หลังเล่นไม่กี่รอบ, และร้าน event token ที่ไม่ใช้เงินจริง
- อนุญาตขาย **ชุดธีมคู่กัน** โดยตรงเฉพาะหลัง Payment Gate ผ่าน; ห้ามขายแต้มกิจกรรมหรือบัฟเพิ่มดาเมจ
- ระบุเวลาแบบ UTC ในระบบ + local timezone ใน UI; มี claim grace หลัง event สิ้นสุด; archive/return policy ระบุหน้า UI
- Daily/weekly objectives ต้องมี alternate path เพื่อไม่บังคับผู้เล่น login ทุกวัน
- ก่อน publish: ตรวจ game build compatibility, item config, localization, server reward preview, budget ผู้เล่น casual, rollback, legal/IP rights

## 7. Sample event earn/spend budget — for playtest
Token Festival 14 days: 6 quests x 25 tokens + 10 normal runs x 10 tokens = 250 tokens สำหรับคนเล่นไม่มาก; ตัวอย่าง free featured skin 180, aura 40, gold sink 30. **ตัวเลขทั้งหมดต้องทดสอบจริง** ว่าผู้เล่น 3 sessions/week ทำได้; ไม่จำกัดรางวัลหลักไว้กับ daily attendance.
- Event tokens ไม่หายโดยไม่แจ้ง; เมื่อจบแปลงส่วนที่เหลือตาม policy ที่เผยแพร่
- Duplicate cosmetic แสดง inventory owned และ hide buy; rerun เห็น alternate compensation อย่างโปร่งใส
- Quest ครบก่อนหมดเวลาแล้ว offline: ต้องแสดง pending claim และเปิด grace หลัง online กลับ

## 8. Event technical edge cases
- Event overlap: active priority เลือกโดย explicit priority ไม่ใช่ตามลำดับไฟล์; quest counters เฉพาะ event ID
- Event rerun: use new instance ID; entitlement same cosmetic cannot grant twice by accident
- Server downtime: suspend claim/extend grace via published incident policy; never client clock for paid/event entitlements
- Timezones/DST/UTC, refresh mid-run, expired event while paused, reinstall, save migration, missed webhook, server retry
- First 4 content events should reuse templates A/B/C; **no new game mode each event** until content production velocity can support it

## 9. Definition of event ready
Brief + event ID + responsible person + story/visual + objectives + fallback goals + free & paid item list + prices (if any) + earned token simulation + assets/licenses + server flags + start/end/claim UTC + mobile/browser QA evidence + rollback + announcement + postmortem metrics.
