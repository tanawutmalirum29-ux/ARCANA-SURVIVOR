# Dormant Event v2 storage boundary (CEO-owned)

**Activation: HOLD**. This is an adapter contract for the offline Events reducer merged from #37. Nothing in the player UI imports or mounts this module. The simulated 2030 Season 01 schedule does not describe an actual live event. No commerce, new cosmetic ownership or paid entitlements are enabled.

`src/integration/eventV2Store.js` requires a synchronous **trusted** injected store with `read(): snapshot | null` and `write(snapshot): true | false`. **`null` is permitted ONLY after an authoritative missing-key check**; if the key exists but JSON parsing, access, decoding, or a transient read fails, the adapter MUST throw and MUST NOT return `null`. Returning `undefined` indicates a broken/missing adapter result and returns `READ_FAILED` with zero writes; it can NEVER trigger fresh initialization. The coordinator now requires **two consecutive confirmed `null` reads** before initialization to catch a transient false-null followed by the real saved ledger. This guard is defense-in-depth and does not make a lying adapter trustworthy. This module cannot infer whether a lying adapter's `null` means absence, so production wiring must establish and test truthful missing-key semantics before activation. A write must atomically commit one complete versioned Events save and return literal `true` only after success. The adapter verifies the persisted bytes by rereading and validates the reducer invariants. A store returning `true` without committing is rejected. This contract does **not** make multiple stores atomic, prove authenticity or replace a server.

`prepareStoredEventState({store,checkpoint})` returns `INITIALIZED`, `LOADED` or `MIGRATED_V1` with `ok:true` only after a validated and, when needed, verified persisted Event v2 snapshot. A clean v1 snapshot migrates explicitly using the Events-owned `migrateEventStateV1` and preserves original claims/outbox/replay identity. Unknown versions, corrupt records and ambiguous v1 Token claim/spend history return error statuses and **never overwrite the old snapshot**.

`commitStoredEventTransition({store,transition,checkpoint})` first prepares the durable v2 save. A caller's pure Events reducer computes a proposed snapshot. It is validated and durably saved/verified **before** the caller can expose the new claim or hand it to the earned-only wallet delivery coordinator. On a failed write/verification it returns a blocker rather than reporting a commit. After power loss, rerun with the same domain eventId; the persisted global replay guard prevents extra credit.

The separate `persistedRewards.js` remains the *wallet-before-outbox-ACK* coordinator. An actual future client integration must first durably commit the Events claim with this boundary, then persist wallet via `settlePersistedGrant`, then persist outbox ACK. If localStorage is the chosen backend, use a distinct versioned key for Events and make write failures visible; do not silently reset token history or migrate unknown legacy saves. The current `src/storage.js` save for wardrobe, its Gold field and the Economy catalog are **unchanged**.

Unit tests in `tests/integration/eventV2Store.test.js` inject crashes before/after migration writes, invalid v1/v2 ledger, failed writes, dishonest storage, replay, persisted claims/outbox, and intermittent or repeated `undefined`/thrown/malformed reads. They assert **zero writes and preserved original replay/claim ledgers** on read failure; verified real `null` still initializes. No actual Chromium/WebKit stored Events browser test or physical Android/iOS performance certification is claimed. Independent QA must review the exact PR SHA before merge; main CI must be checked afterward. The safety-blocked Economy catalog work in #24 remains untouched.
